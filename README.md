# Agent Skills

Reusable [Agent Skills](https://agentskills.io) for coding, architecture, and engineering process work.
The same `skills/<id>/SKILL.md` layout works with **opencode** and **Claude Code**.

## What is a skill?

A skill is a directory with a `SKILL.md` file containing YAML frontmatter and Markdown instructions.
Agents advertise the `description` and load the full body only when the skill is relevant, so many
skills can be installed without bloating every prompt.

Optional supporting files live beside `SKILL.md`:

```text
skills/<id>/
├── SKILL.md
├── references/   # detailed material loaded on demand
├── scripts/      # self-contained helpers
└── assets/       # templates and static resources
```

## Install

```bash
git clone <repo-url> ~/repos/skills
cd ~/repos/skills
make install
```

`make install` symlinks every skill into the agent discovery directories:

- `~/.config/opencode/skills/`
- `~/.claude/skills/`

Each skill is linked individually, so this repository can coexist with other skill sources.
Use `./scripts/install.sh --copy` on filesystems without symlink support, `--target <path>` for a
custom directory, and `--uninstall` to remove only links that point into this repository.

After installation, opencode and Claude Code discover the skills automatically. Load one explicitly
with `@<skill-id>` in opencode or `/<skill-id>` in Claude Code.

## Repository layout

```text
skills/            # one directory per skill (flat, portable IDs)
templates/skill/   # starter SKILL.md for new skills
scripts/           # install, validation, catalog generation
catalog.json       # generated catalog of installed skills
```

Skills are intentionally **flat**: opencode derives a skill ID from the directory name, and other
Agent Skills clients expect `skills/<id>/SKILL.md`. Categories live in frontmatter metadata and in
the generated catalog above.

## Adding a skill

1. Copy `templates/skill/` to `skills/<id>/`.
2. Set `name` to the directory name (lowercase kebab-case).
3. Write a `description` that says what the skill does and when an agent should use it.
4. Keep `SKILL.md` under 500 lines; move details to `references/`.
5. Run `make check` and fix any errors.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full conventions.

## Validation

```bash
make validate   # frontmatter, naming, links, size
make catalog    # regenerate catalog.json and the table above
make check      # validate + verify the catalog is up to date
```

`make validate` also runs `skills-ref validate` for every skill when that tool is installed.
